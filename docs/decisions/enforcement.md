# KidGuard decisions: enforcement

Index and the rule for adding lines: `README.md`.

## Decided
- 2026-11-13 What a bank-app pause takes away is computed: `Features.PAUSES` (pause -> caps) + `Features.lost()` over `Features.TABLE`; the kid popup / notification never carry hand-written feature lists (FeaturesTest fails on a missing row / name).
- Release (`release` cmd) must undo every restriction; a failed release re-applies policy + watchdog, keeps parent tokens and keeps enforcing (1747923, f032b5d). Release aborts with "failed: N app còn bị ẩn" if a Dọn máy-hidden app can't be un-hidden
- Basic mode (no Device Owner) exists for phones that can't be DO without a PC (no QR setup, Android <11): accessibility bounces blocked apps HOME, bounces Settings/installer pages that would uninstall/deactivate/force-stop us; self-protection only after first pairing (43b298f, 831bf98)
- Features without full setup: feature->capability table (Features.kt, state.caps/features); launcher works without DO via local opt-in before pairing, parent rule after; only owner forces home (d1c75da)
- Dọn máy without DO: through the phone's own Wireless-debugging adb (`pm disable-user`/`enable`/`clear`); only re-enables packages recorded in Store.shellDisabled; max 20 per pass (d1c75da, agent C). The parent page gated it owner-only until 2026-11-09; now basic mode gets Dọn máy + Xoá dữ liệu whenever state.preinstalled is sent (= SelfAdb.ready)
- HyperOS 3 (Poco, SDK 36) refuses `pm disable-user` AND `pm hide` from shell for system apps ("Cannot disable system packages"), so basic-mode Ẩn app failed for all 23 (2026-11-11). `pm suspend` works but leaves the icon. Fallback in `Debloat.disableCmd`: `pm uninstall -k --user 0` (APK + data kept; undone by `cmd package install-existing` in `enableCmd`, also on release); hidden check = disabled-user OR not FLAG_INSTALLED for the user. Verified by hand on the Poco (remove + restore).
- Clock events say what happened (2026-11-12): a jump reads "set 2 h 5 min fast: shows 11:06, real 09:01" (real = last tick wall + elapsed since), basic-mode auto time / auto zone switched off says which switch and whether KidGuard turned it back on. The bare "Giờ máy bị đổi" left the parent guessing. Poco check that day: `dumpsys alarm` mLastTimeChange*, `cmd time_zone_detector dump` and `dumpsys settings` (last writer pkg of auto_time*) show what really changed.
- Basic mode + WRITE_SECURE_SETTINGS (cap `wss`, 2026-11-10): `lockLocation` and Safe DNS work without Device Owner and without a live adb shell (survive Developer options off): `Guard.keepLocation` re-writes location_mode, `Policy.keepDnsWss` + ContentObserver on private_dns_* re-apply the host, `DnsLogic.plan` (pure) restores the prior mode/host on pause / release (`Store.dnsByWss`). Chrome/Edge DoH-off stays owner-only. Unverified on a real phone (Android 10+ `location_mode` write, drift between observer and re-write).
- Safe DNS fallback: after ~90 s unvalidated falls back to opportunistic; retries host after 30 min; keeps DISALLOW_CONFIG_PRIVATE_DNS (60811e2, f032b5d)
- Time-change / timezone change / usage-access-off are parent events (clock / tamper) (f032b5d)
- Location lock works on Android 8 via LOCATION_MODE + content observer (5f03cbe). Location history asks network+gps together on Android <12 (gps alone never answers indoors) and removes every one-shot listener (41cf1f9)
- Device-health, chores, zones (arrive/leave), alerts as state.events, FCM push carries no text (747bc65, f508a30)
- App groups (shared limit + hours), Google-Authenticator-style offline unlock code (RFC 6238) (ceab74c)
- devOff (Developer options/USB debugging off, because banking apps refuse to open with them on); noDebug off->on also runs devOff once (0998bdb). Never press devOff on the dev Oppo (kills adb)
- Remote settings: volume/brightness/timeout/DND via `setting` cmd, state `sys` read at most once a minute (318b4ca)
- Quick-settings blocking: rule `launcher.shade` (parent toggle, default off) closes ONLY quick settings via Acc; notification shade stays usable (5b81268, user: "tuong dong control center thoi")
- showWatching rule (default true); notice switches to "Bố mẹ đang điều khiển máy" after first input; log always records (882cd92)
- Guard `tick()`: optional steps (usage, DNS retry, Tailscale poll, location, battery, warn, history, update, launcher) run through `opt{}`, so one throwing never skips suspend/hide; failures are logged once a minute per step.
- Release moves `NotifDots.setOn(false)` after Device Owner is really gone and restores `tsWanted/tsKey/tsNoExpiry` when release fails; `Debloat.canClear` refuses `dev.kidguard` and `dev.kidguard.home`; LAN file upload is capped at 10 min total; `Store.ringVol` lets the Guard restore the alarm volume after a process death mid-ring.
- Bank apps (VCB & co.) refuse to run while ANY accessibility service is on, Play Store ones too (Niagara Launcher, owner report), and re-check on every resume. Rule `accPause` (default ~15 VN banks/wallets): owner mode really removes our service when one opens (launcher tap first, else its window event), back on after 10 min with none in front + killBackgroundProcesses on them. Not "hiding" from the check. Basic mode: same when the app holds WRITE_SECURE_SETTINGS (adb / Wireless-debugging setup), back on after 1 min instead of 10 (the service is the enforcement); before 11-09 evening `able()` required Device Owner so the Poco (basic) never paused. Recents re-open after resume may still lose the race (unverified) (11-09)
- Location pace: a good history fix is also the "last location" (no second GPS run per 15 min); a still phone (2 same-spot fixes, screen off, significant-motion sensor armed) takes 1 fix / 15 min + 1 refresh / h. Never slow without the sensor: a child leaving must be seen. `LocPace` (0.9.18)
- (2026-11-10) Basic mode: a bounce now also pauses the bounced package's playing media session (`BasicMedia`, needs notification access, else skipped); clock tamper without DISALLOW_CONFIG_DATE_TIME = tick rewrites auto_time / auto_time_zone to 1 when WRITE_SECURE_SETTINGS is held (logs the "clock" event on 1 -> 0) + Acc sends HOME from the Date & time page (text match; also blocks the parent from setting the clock on that phone). Neither verified on a device.
- Rule `monitor` ("Chỉ theo dõi"): `decide()` stays pure and always runs; `enforced(r, would)` empties it in monitor mode, so suspend / bounce / launcher / Quick tile see nothing while `state.wouldBlock` + a log line report what strict mode would do. Device-level `Policy.apply` restrictions and all reporting are unchanged; heads-up warnings are off.
- Location history (2026-11-11, owner): 1-min step added, default 5 min (was 10). Same spot = one point per 10 min whatever the step; "moved" = distance beats max(30 m, either fix's accuracy), a ±150 m+ fix never moves; the last same-spot fix is stored before the first moved one so "Rời X hh:mm" is exact. Page shows a journey (arrive / leave per stop, trip time + km) instead of a bare stop list.
- Dọn máy in basic mode (2026-11-11, owner asked "cần Device Owner à?"): no, it works through the self-adb shell, but the list was hidden whenever that shell was down (Poco on 4G) and the page blamed "no Device Owner". Now the list shows once self-adb is set up, hides wait for Wi-Fi, and state `adbWhy` drives an exact reason.
- Protected apps (`Policy.protectedApps`, 2026-11-09): exempt from every limit = our package + system apps (HOME/dialer/alarm handlers, system keyboards, SMS/dialer default if system). A non-system default dialer or SMS app is limited like any app (emergency calls go through system `com.android.phone`/telecom, still protected). Dead-end exceptions kept exempt: a non-system default HOME (suspending the only home screen leaves no way to open anything) and the current default keyboard (no way to type the PIN); the HOME case raises a `tamper` event once per package (`Policy.foreignHome`, Guard tick), so the parent can remove the app or `hidden` it. Other enabled non-system keyboards are no longer exempt.
- Safe DNS timed pause (`safeDnsPauseUntil`, 2026-11-09): an absolute end time in the rules, not a command, so it works over LAN and relay alike and survives phone reboots; `Policy.syncDns` (Guard tick, 10 s) re-applies when the effective host (`Rules.dnsHost`) changes, so expiry needs no alarm. Compared with the phone clock: a parent clock far off shortens/lengthens the pause (same caveat as `pausedUntil`).
- Browser DoH vs safe DNS: with `safeDns` on, `Policy.applyDoh` pushes managed config `DnsOverHttpsMode=off` to Chrome (stable/beta/dev/canary) and Edge (policy exists on Android from Edge 147); cleared when safeDns is off and in release. Firefox Android has no managed-config/AppConfig support (Mozilla only turns its DoH off itself when enterprise policy/parental control is detected), Brave/Opera unverified: documented limitation, not blocked. Unverified on a real phone.
- Safe DNS presets (page `DNS()`): CleanBrowsing Family `family-filter-dns.cleanbrowsing.org` and AdGuard Family `family.adguard-dns.com` force SafeSearch (+ YouTube restricted, "where possible" for AdGuard; CleanBrowsing's YouTube level is Moderate/Strict per differing pages; the YouTube app may bypass); Cloudflare Family `family.cloudflare-dns.com` only blocks adult/malware (no SafeSearch). Plus "custom host".
- `noVpn` rule (default false): `DISALLOW_CONFIG_VPN` via `Policy.applyVpnLock`, the single owner (set if `noVpn` OR `Store.tsWanted`; Ts.kt and release go through it). It blocks the VPN settings UI and adding/enabling VPN profiles by the user; it does not uninstall VPN apps and an app the user already consented to may keep running, which we cannot stop without removing the app (use blocked/hidden apps). Our Tailscale always-on VPN is set by the DO and unaffected. Unverified on a real phone.
- (2026-11-10) Adb window (SelfAdb.ensure): Developer options stay off (banking apps); with WSS KidGuard switches dev options + Wireless debugging on only for a shell job and back 20 s later. Opens only on a real hide/unhide diff (refused apps excluded) so it never flaps every 10 min. Unmeasured on a phone: whether adbd comes up on a network never trusted by hand, and how long
- (2026-11-10) Bank reopen after pauseLate: if the bank was opened by a notification tap (NotifLog.recentClick, 8 s), that notification's PendingIntent is sent again so the deep link survives; held in memory only (lost when the process dies), and only recorded while the notification listener is on
- (2026-11-10) Wrong-PIN photo (`pinShot`, default on): front camera only, 3rd/6th… wrong admin code, >= 2 min apart, told on the PIN dialog (no hidden camera; Android 12+ shows the dot anyway), 7 days on the phone, release deletes. Only the on-device admin dialog, not the pairing PIN. Shot.kt.
- Self-protect name match is whole-name (`BasicLogic.names`: no letter glued before, only punctuation/end after), replacing the substring rule above: "KidGuard Home" / "KidGuard Pro" pass, "Gỡ “KidGuard”?" still closes. Home flavor is protected only while it is the HOME. Controls also come from the Settings app's own localized strings (Acc `CONTROL_IDS`: uninstall_text, force_stop, ...) so any phone language works; OEM pages without them fall back to the vi/en lists. Every auto-close shows a short toast (MIUI cuts toasts at 2 lines).
- PIN gate (2026-11-11, owner: a leaked parent link must not remove KidGuard): dangerous commands carry the parent PIN / TOTP, checked on the PHONE (`CmdGate`), never trusted to the worker; rules PUT can no longer replace a set PIN (was the forgot-PIN path) → `pinSet` with old PIN or `pinReset` (24 h delay + alert, old PIN cancels). openPairing gated too (link can watch the screen = read the code). Not gated on purpose: rules edits, lock/ring/screen (everyday, one tap); a link holder can still loosen rules (logged as ruleDiff). PIN sent in clear inside the TLS command body: hashing a 4–8 digit PIN adds nothing against whoever reads the queue (10k guesses offline).
- Bank vs debugging (2026-11-11, owner): SPLIT from the accessibility pause into its own rule `devPause` (column "Gỡ lỗi"), own resume timer (DevOpts.tick), toast "Đang tắt gỡ lỗi để mở X…" while the start waits for adbd. Why: most banks only check accessibility, and tying debugging to them dropped adb + delayed every bank open. Old phones (no `devPause` in rules) keep the old coupling on the page label "Trợ năng + gỡ lỗi". Default list: My MobiFone only; website list flag `dev`.
- Bank list sync (2026-11-11): bundled DEFAULT reached only new installs (Cake, My MobiFone missed on live phones); now daily from Pages, add-only-never-seen (parent removals stick), blocked apps never pause acc (a tampered list cannot whitelist a game).
- VPN pause separate from acc pause (2026-11-11, owner): apps check one or the other, so two rule lists, one page list with two boxes. Only Tailscale obeys (DISCONNECT_VPN); always-on lifted only as Device Owner (basic: Settings-only, WRITE_SECURE_SETTINGS always_on_vpn_app is not applied live).
- Remote adb shell + port 5555 (2026-11-11, owner: "gửi terminal lệnh adb từ web"; "app có quyền adb rồi sao bắt cắm dây"): `adbShell` runs through the already-paired on-phone adb (no new privilege), PIN-gated like release (a leaked link must not get a shell), not on Telegram, output via state `sh` (memory only). `adbTcp` keeps USB debugging on + `tcpip:5555`, re-done after reboot (the prop isn't persistent and shell can't set `persist.adb.tcp.port`); default off because it keeps debugging on (banks: DevOpts pause still applies) and exposes a port on the Wi-Fi.
- Self adb over 127.0.0.1:5555 (2026-11-11, owner: "t có 3g thôi"): Wireless debugging needs Wi-Fi, but adbd serving 5555 (adb tcpip) accepts the key paired once, on any network. `SelfAdb.connect` tries :5555 first (timeout 10 s, throwOnUnauthorised: libadb default waits forever for the "Allow?" prompt while holding the lock), then mDNS. Limit: after a reboot 5555 is closed and reopening needs Wi-Fi once (or a cable).
- Fable review of the adb terminal (2026-11-11): state `sh` capped (big outputs × 8 would 413 the relay state and block all relay commands), `SelfAdb.service` has a 10 s closer (held lock = Guard tick stuck), `why()` cheap checks before the mDNS probe + NO_MS 5 min (basic mode probed every 30 s), `usb:` retried after `adbTcp` off (tcp port prop survives adbd restarts), page `sig` includes `sh` / `support` (outputs never redrew).
- Review 2026-11-11 (second pass, v0.9.14): `AccPause.pauseLate` does nothing without WRITE_SECURE_SETTINGS or for a blocked app (it used to `disableSelf()` anyway: basic mode lost all blocking after one bank-app open); `Ts.undo` uninstalls Tailscale only when we installed it (`Store.tsOurs`, default true for phones set up earlier) and clears always-on only when it points at Tailscale; page `kidRules` picks the relay's stored PUT only while its `rev` is newer (template to several kids undid LAN / Telegram changes); parent-app Grant is idempotent per request (`bonus:<req>` mark, HALF result retries only the `answer`; the page cannot see that mark, a phone-side bonus in `answer` would need a protocol change) and shows "sent" for relay `queued`; launcher drops its in-memory model while stopped (stale copy overwrote Tuỳ chỉnh saves; no drawing change, so no perf run); state JSON is built on read (`Guard.currentState`, `stateTodo`) instead of every tick; setup permission steps open app settings once Android stops showing the dialog; the "can't connect" card has Forget. Same pass, lows: Telegram Yes claims the request through `answer` with `req` (a repeated command `id` answers "ok" without running, so `id` let a second parent's tap add the bonus again); unlinked chats get one bot reply per 5 s; `Files.pull` keeps the relay copy on "no space" and logs it; parent-app `CheckJob` falls back to the kid's relay and says "unpaired" for a LAN kid only when `/api/hello` still returns its id (closes the 2026-11-10 "Not done" above; the page does the same before forgetting a kid), a LAN-only kid on another subnet does not count as lost; page rules PUTs are queued per kid; `Push.sync` only when the relay-kid set or token changed; launcher: unpin works inside a folder, a gesture / notification reopen uses the icon tap's hidden/paused check, `HomeBackup.apply` saves the layout before replacing photo and gestures. Measured and left alone: state size (emulator prefs 37 KB total, log 50 lines, track capped: far under the relay's 120 KB), `Policy.apply` (~20 binder calls, once per rules save), per-tick `queryEvents` replay (Poco: ~6.2k usage events in the dump window; an incremental cache changes how screen time is counted and needs a phone test first), relay `?since` / slim state for CheckJob (page open 8 h = 3,600 of 100k requests/day).
- (2026-11-11, later) The phone-side day query above was built after all (owner wants history older than the page): `HistDb` SQLite `kghist.db` (logs + events, 90 days / 30k rows, writes on one background thread, prefs rows imported once, deleted on a successful release), LAN `GET /api/logday?day=`, relay `POST/PUT /logday` shaped like `/device` (not a command; worker keeps 4 days, answer <= 90 KB / 500 rows so MAX_BODY and the 128 KB DO value cap hold). State still carries only 50 + 50. localStorage `kg.lg.<id>` stays only as the fallback for phones / workers without the route. Note: location history is NOT SQLite (prefs JSON, 7 d / 3000 points); this is a new store.
- 2026-11-13: port close split into its own list `tcpPause` (column "adb port"): a shell-uid helper dies with adbd and `setprop service.adb.tcp.port` is denied to shell on HyperOS, so the port only comes back over Wi-Fi debugging or a cable; apps that only check debugging keep the port. Kid home shows a popup before such an app opens (what goes off / what stops / how it comes back), "don't ask again" per app (Store.pauseNoAsk).
- (2026-11-13) Home lock in basic mode (`LauncherLock` + `LauncherLockLogic`): Acc closes the Settings "Home app" page / HOME ResolverActivity and bounces only real HOME activities of other launchers (class must be in the HOME query, so MIUI Recents in com.miui.home is not bounced); self-adb `set-home-activity` is optional (it only stops the flash, Acc alone enforces); bypassable by Safe Mode / Acc off; titles per OEM unverified, no device test
- 2026-11-13 Phone health tab (storage tab renamed): score = 100 minus weights of REAL checks only (HealthLogic: dev options, device admins, sideloaded, patch age, free space, cache, background apps); no fake "speed up %" / virus scan. "Fix all" = clearCache + bgLimit + devOff, one by one. bgLimit = `cmd appops set RUN_ANY_IN_BACKGROUND ignore` via self-adb for user apps minus protected / allow / bank lists, remembered in Store.bgLimited and set back to allow by release / bgRestore. Kid "Dọn dẹp" tile (rule kidClean) runs only clearCaches, 10 min apart; kid never gets bgLimit. Not checked on device: appops output format of `cmd appops get`.
- 2026-11-13 Phone health fixes must be reviewable (owner: "Fix buttons are scary"): no one-tap "Fix all"; "Xem & sửa" sheet = switch per change with effect + undo (cache ticked; background limit only for `bgIdle` apps and dev options start unticked); every row Fix asks what it does / what the child sees / what changes in KidGuard / undo. Background apps: per-app list with locked rows (`bgKeep`), search, "Gợi ý" = `bgIdle`, per-app undo (`bgRestore {pkgs}`). Dev options on while KidGuard's own adb is usable = info, not an issue (0 points): devOff kills clear-all-caches, bgLimit AND bgRestore, adb terminal, auto-grants. Not checked on device.
- 2026-11-13 Admin secrets (audit H1, owner): PIN first, Authenticator code as its backup (owner: "nhiều đường mở"), also while the PIN is locked. A code may be one read out to the kid for an unlock, so opening admin with a code raises a `tamper` event (Telegram alert) and a PIN open raises `adminOpen`. Rejected: PIN-only admin (parent locked out when the kid spams the PIN).
- 2026-11-13 Wi-Fi debugging port 5555 closes itself after 2 h (`adbTcpUntil`, M12); Telegram typed action commands older than 10 min are refused (M8; button taps are not dated by Telegram); `Http` caps 14 open connections per remote address (L10); proxy Content-Type allow-list in the parent app (L31); release retries `bgRestore` at start and logs apps still background-limited (M9).
- 2026-11-14 Phone core 0.9.16: passes are `passUntil` (not the bonus) whenever something other than the daily limit locks the phone; SIM change = state/operator/carrierId only (no READ_PHONE_STATE, a same-carrier swap is invisible); lost mode locks on `USER_PRESENT` not `SCREEN_ON` so the lock-screen text stays readable; release raises `released` and syncs BEFORE `clearTokens` (creds captured first, then `/forget`); on-device PIN attempts have their own counter so a child cannot lock the parents' remote access.
- 2026-11-14 Lost mode relock: every unlock shows the lost card first (message, call-back number, "Parent: turn off"), Device Owner locks again after 20 s; a right PIN / Authenticator code on the phone stops the relock for 10 min so a parent holding an offline phone can end lost mode (instant lockNow made that impossible).
- (2026-11-14) Factory reset protection (A6.8, rule `frpIds`, Device Owner + Android 11+): the API takes the numeric Google account ID, not the email. No in-app way to read it (Play Services keeps it private), so the parent pastes it (OAuth Playground + People API `people/me`, how-to under the field). Wrong ID can brick the phone after a reset: the text says so. Cleared in `Policy.release`. Not tested on a real reset.
- 2026-11-14 Lost mode parts are optional (owner): rules `lostLock` / `lostRing` (default true); locating every 5 min is always on. Turning ring off mid-alarm stops it on the next tick.

## Rejected / don't retry
- `DevicePolicyManager.setStatusBarDisabled` for shade blocking: also sets mDisableNotificationEffects, silencing ALL notification sound/vibration/heads-up (measured API 34). Also don't use lock-task status bar flags. Use Acc quick-settings closing (11-09)
- Generic "uiautomator dump" on the dev phone while testing accessibility: it suppresses other a11y services (Acc looks off). Use screencap (v0.7.0 notes)
- Keystroke / keyword monitoring (FamShield does it on Windows): rejected, conflicts with "the child always knows"; see docs/research-famshield.md
- (2026-11-10) Rejected: hiding the foreground notification from code. A channel created at IMPORTANCE_NONE (new id, old one deleted) is raised by the system to LOW (2) as soon as the FGS posts (mUserLockedFields=0), measured on API 34 emulator + Poco API 36; WRITE_SECURE_SETTINGS / Device Owner have no per-channel block. Only the user turning the channel off hides it, and that holds across a real process kill (emulator, kill -9, service back in foreground, notification still hidden).

## Past bugs (cause -> fix -> avoid)
- Failed `release` left phone owner but unenforced (loop stopped on anything but "failed"). Fix: any non-ok result resumes enforcing (f032b5d)
- Un-hiding an app logged a false "Cài mới" -> fixed 7fc1506
- Basic mode loops: accessibility detail page bounced forever (selfProtect before first pairing), Settings opened in own task, FallbackHome counted as home app (opening About phone dropped child to home) -> gate on everPaired, NEW_TASK (831bf98, 92f58e8)
- Location track sparse on Oppo -> network+gps together, listener cleanup; gps was left on for hours (41cf1f9)
- Bank still refused after the debugging pause (2026-11-11, Poco, My MobiFone 50052): adb_enabled=0 at 12.128 but adbd lived until 13.228 and AppSealing killed the app at 12.790 -> launcher (icon, shortcut, gesture) and the Acc relaunch wait for `init.svc.adbd` to leave running (`DevOpts.afterOff`, poll 100 ms, max 3 s; unreadable property = fixed 1.6 s). Avoid: never assume a settings write stops a daemon at once.
- Bank vs adb over the network (2026-11-13, Poco, My MobiFone 50052): debugging off + adbd gone 0.3 s before the start, still refused; `service.adb.tcp.port`=5555 survives adb_enabled=0 (until reboot) and AppSealing reads it. After `adb usb` (port prop 0) it opened. The devPause now runs `usb:` over our own adb first when the port is set (`DevLogic.tcpOpen`; unreadable prop = rule adbTcp), off the main thread, `afterOff` holds the start (max 6 s). Cost: after the resume the port reopens only through Shell.tick, which needs Wi-Fi (or the port) for our adb: on 4G the 5555 port stays closed until Wi-Fi.
- (2026-11-10) Basic-mode kid launcher deadlock: paired non-owner used rule-only (launcher.on), the page gated that checkbox on cap "home" (= already default HOME) and the phone's button did nothing once paired, so KidGuard vanished from the HOME list for good. Now non-owner ⇒ HOME component always enabled (nothing can be forced without DO anyway); only safe mode / release disable it. r-home section is never gated
- (2026-11-10) Basic-mode bank pause gap: the accessibility service is the app blocker, so while paused (bank in front + 60 s) nothing was blocked. `AccPause` now watches usage events every 2 s only while paused + screen on (one queryEvents over ~3 s, ~1-3 ms; the 10 s tick already reads since midnight) and resumes the service the moment a blocked app is in front; `Acc.onServiceConnected` checks the window already in front (no event comes for it). Reopen after `pauseLate` needs SYSTEM_ALERT_WINDOW in basic mode (Device Owner is exempt from background-start limits): optional setup grant in all 4 paths + self-adb grant + Features row
- Basic-mode self-protect matched "KidGuard" by substring, so "KidGuard Home"'s app info closed at once and the owner could not uninstall it. `BasicLogic.selfProtect(free=)` now skips names that only contain the label; Acc passes the Home flavor's label unless dev.kidguard.home is the phone's HOME (then it is the kid's launcher and stays protected).
- 2026-11-13 App sizes: StorageStats.dataBytes already includes cacheBytes; app+data+cache counted the cache twice (Poco Play Store showed 10.9 GB, real 5.6 GB of which 5.5 GB cache). "Dọn" offers clear cache (pm clear --cache-only, self-adb, keeps logins) before clear data.
