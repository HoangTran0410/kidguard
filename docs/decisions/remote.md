# KidGuard decisions: remote

Index and the rule for adding lines: `README.md`.

## Decided
- Telegram alerts go through the relay worker only (secret TG_BOT, own bot per family, webhook path = hash of the token); LAN-only families cannot use them. Text only, same events as FCM, no inline buttons (answering stays in the page)
- Pairing: PIN required once set; 5 free tries then 5 min lock, doubling; every 3rd wrong pairing guess rotates the code; code checked BEFORE PIN so wrong PINs alone can't lock pairing (66d8d5d, f032b5d)
- "Reopen pairing" when paired with no PIN opens only after 24 h (Store.recoverAt) and notifies parents; a PIN cancels it. Reason: otherwise the child pairs its own browser and releases (7fc1506). A "Chưa đặt PIN" banner on every tab pushes parents to set one (d39f9dc)
- Listen (mic): one-way, beep + ongoing notification + log, max 10 min, one listener, refused if its notice channel is silenced, child always told (d7fed7a, 747bc65). Legal-risk item per CEO review
- Tailscale: auth key only typed on LAN, never queued on relay (`tailscaleOff` whitelisted only); API access token mints the kid's own key and disables its 180-day expiry; token memory-only (882cd92, 678c8ba)
- Self-update from GitHub releases: daily check (rule autoUpdate default on) or `update` cmd (deliver-once); checks sha256 + package + versionCode; DO installs silently, basic shows notification + button (e461efe)
- (2026-11-13) Basic mode self-update without the child (Android 12+): `setRequireUserAction(USER_ACTION_NOT_REQUIRED)` + `UPDATE_PACKAGES_WITHOUT_USER_ACTION` + appops REQUEST_INSTALL_PACKAGES granted at setup (4 setup paths, AutoGrant, on-phone step). Only works once KidGuard is its own installer of record (an adb / browser install is not), so the first update after setup may still ask; refused -> the old notification. Setup never granted "install unknown apps" before v0.9.16: the child got the permission prompt at update time.
- Command whitelist lives in the relay worker; new command = whitelist + protocol + test. Destructive (`reboot`, `release`, `unpairAll`, `update`, `unpair`) are deliver-once (AGENTS.md)
- Worker caps: cmd <=4 KB, rules <=64 KB, full queue -> 429 (never drop oldest), per-IP 150 req/10 s on /c/*; state size counted in bytes; expired cmds don't count (1747923, 66d8d5d, f032b5d)
- Worker gives every command a random id, so SOS ack uses field `sos`, not `id` (f032b5d)
- Rules carry `pinAt`; phone takes a relay PIN hash only once (the relay re-sent an old hash and reverted a LAN-changed PIN) (f032b5d)
- LAN server rejects non-IP / non-.ts.net Host headers (DNS rebinding); CORS on /api only for other KidGuard phones (private IP/LAN name/*.ts.net), never Allow-Credentials (66d8d5d, 4a2a75a)
- ~~Tailscale first, relay under Advanced; per-family self-host relay because the shared free relay supports only ~20-50 families (546465e, CEO review)~~ REVERSED 2026-11-10 (owner): ease of setup first: the author's relay is on by default once paired, `/go` link always opens; self-host relay = advanced. Load: ~2k syncs + ~1.5k storage writes per kid per day -> free plan ~45 kids; plan = WebSocket hibernation (see support-matrix / protocol when done)
- Relay state is hashed per minute (usage counters) -> ~3x fewer full states (1747923)
- Live screen: Android 11+ takeScreenshot via Acc; Android 8-10 via MediaProjection with one child consent (Proj.kt). LAN frame loop up to ~7 fps (3dcd7a0)
- Listen player uses MediaSource: first sound ~0.3 s instead of ~8 s (ffcebd0)
- Wi-Fi high-perf lock on demand on Android 10+ (3 min after a LAN `/api` call, or while listen / screen view); Android 8-9 keep it always (ColorOS 8.1). `PowerLogic.wifiPerf` (0.9.18; battery not measured on a phone yet)
- Automatic self-update installs only with the screen off (24 h cap); the parent's "update" installs at once. The install kills the launcher mid-use otherwise (0.9.18)
- Telegram: long answers are split at line ends into several messages (was cut at 4000); >= 4 plain events at once = one digest message per chat (tamper / new app / photo / SOS / requests stay single); getUpdates 429 waits `retry_after`, other errors back off 5 s -> 60 s (0.9.18)
- Relay worker: a new shared file arms the DO alarm at its 1 h TTL (chunks used to stay until the next request); a full icon list (400) drops icons of apps no longer in `state.apps`, the phone forgets removed apps so a reinstall re-sends (0.9.18)
- Tailscale setup retry gap grows 5 min -> 30 min -> 6 h (each try downloads ~40 MB), failed install sessions are abandoned (0.9.18)
- Relay `fileUp` / `shotUp` answer "ok" = started; a failed upload is a log line the parent reads (`log_file_push_fail`); a relay file that failed to save is retried 10 min later, not every sync (0.9.18)
- HTML needs X-Frame-Options DENY + CSP; new external origins (tiles) must be added to CSP on phone AND worker
- Parent app = WebView + localhost proxy serving ui/; only our own origin plus OSM tiles reachable; caches last state (X-KG-Cached banner); 8 s state timeout so a stalled phone falls back fast (625bbc2)
- Update notification opens the in-app Settings screen instead of a github.com link (the GitHub app hijacked those) (4445879)
- Parent app self-update verifies `kidguard-parent.apk.sha256` (release asset from build.sh) before the installer opens; CheckJob posts one "kid unpaired" notification on 401/403 (flag in Store, cleared when the kid answers again)
- 2026-11-14 Relay receipts + forget (0.9.16): a queued command dropped unrun (SHORT 10 min / 24 h / ONCE window) is kept as `{id,type,res:"expired",at}` (last 10) and returned as `expired` by `GET /state`; `POST /c/<id>/forget` (token) wipes a released kid's storage (Gate bind counters are per IP, not freed). Parent app: 4 channels (sos high, requests default = more time + tamper/lost/released, info low, offline low), notification buttons = N / 2N / Decline (the N/2 of the page does not fit Android's 3 actions), "offline since HH:mm" dismissed when the phone is back and silent while `now.why == "bedtime"`, push registration forced once a day, notification permission asked when the first kid is added (not at launch). Relay push for an app request is an `ev` ("check this kid now") so no app name goes to Google.
- (2026-11-12) Crashes go to the census crash table by themselves (owner: "gửi tự động, dùng chung census bên tv-remote"), app `kidguard`, next start after the crash, SupportScrub'd, no switch. tv-remote must not hear of them: its worker accepts `kidguard` for crashes only (not pings), `crashes.py` drops those rows unless `--app kidguard`, and `~/.tv-remote-release/crashwatch.py` (outside both repos) shows a separate macOS notice, never news.txt.
- Relay bandwidth (2026-11-11, Poco netstats: ~20 MB/day up, 1.5-2 MB down): whole states (2-day track, every app) went on every change and every 5 min. Now partial states (changed keys, apps per pkg, new track points; worker `mergeState`), whole only until the worker says `merge`, on `full`, or every 6 h. Telegram long-poll (~1.5 KB/min down) kept.
- (2026-11-10) Relay load: phone keeps a hibernatable WebSocket to its Durable Object (own RFC 6455 client, no OkHttp); pings are runtime auto-responses (free), the relay kicks instead of the phone polling, `seen` from ping timestamps (an open socket alone is not "online"), seen written on close only. HTTP polling kept as fallback. Estimate per kid per day: before ~2,000 requests + ~1,500-2,000 writes; after ~60-120 requests (reconnects + messages/20) + ~150-400 writes.
- (2026-11-10) Telegram: the CHILD PHONE is the bot (getUpdates long-poll with the family's own @BotFather token), chosen by the owner over a shared bot on the relay: no relay / LAN / Tailscale, data never on our relay. Link = 6-digit code from the page, max 5 private chats. No release / unpair / clear data / reboot over Telegram. The older relay-webhook alerts (TG_BOT) stay in the worker but the page no longer offers them (same token cannot serve a webhook and getUpdates). Tg.kt / TgLogic.kt.
- (2026-11-10) Telegram bot UX: buttons first (/menu inline panel + persistent reply keyboard, sub-panels edited in place), commands still typed; link by t.me/<bot>?start=<code> deep link / QR instead of typing the code. Long-poll answers in ~1 s (Telegram holds the request until a message arrives; 50 s is only the idle timeout).
- Telegram alerts: marked seen only after a chat got them (retry 30 s, drop after 24 h); a voice /rec also gets a Download button (voice can't be saved as a file on every client). (2026-11-10)
- Relay (2026-11-10): DOs GC'd after 30 days without the phone (alarm); icon `?k=` is sha256("icon:"+token). Not done: a Cloudflare WAF rate rule on new ids (dashboard, owner) and a first-bind size cap (real first states size unknown).
- Phone relay WS: a socket that dies within 5 min counts as a failure (backoff 1..30 min), so a flapping network doesn't reconnect every loop.
- (2026-11-10) Tailscale keep-alive in BOTH modes (`Ts.keep`): CONNECT_VPN broadcast, then open once from our home screen (same background-start right as the bank flow). It was missing because Ts.kt only cared when KidGuard installed Tailscale (Device Owner); docs/flows/ had no bank flow nor privilege map, so the existing background-start path was overlooked. Privilege map = docs/flows/README.md §0.
- (2026-11-10) Tailscale keep-alive is opt-in (rule `tsKeep`, default off), owner: a Tailscale installed for work must not be forced on; families on Telegram/relay only don't need it. Always on for KidGuard-installed Tailscale (tsWanted). First version keyed on "a tunnel was seen" (tsSeen): dropped.
- (2026-11-13) Tailscale "up" = a 100.64/10 address on a `tun*` interface only: carriers use the same range for CGNAT (Poco on Viettel 4G: `ccmni3` 100.118.x), so the range alone kept keep-alive asleep while HyperOS Security "clean" (`am_kill GarbageClean` / `OptimizationClean`) had killed Tailscale for 12 and 29 min. Always-on VPN cannot be set live without Device Owner.
- Relay front door (2026-11-11): "/" stays the parent page (bookmarks, /go), but with no phone in this browser it shows a "Get started" card (install `/install`, Device Owner `/qr`, how to pair, the guide), and a short "Add a phone" card under the list. Was a dead-end one-liner.
- Support report (2026-11-11, owner: "giống tvremote, dùng chung"): phone -> tv-remote census worker (`/v1/support`, app `kidguard`, read with its `support.py`), allow-list facts + scrubbed own logcat + last crash; a child's phone, so NO live-look mode, no location / notifications / notes / app list, one app only when the parent picks it. One UI: the parent page tab "Gửi lỗi" (also the on-phone admin page). Replies polled every 6 h. The KidGuard menu also sends WITHOUT the PIN (owner: a parent who forgot the PIN must still reach support; the report holds nothing private, census caps 20/day); reading / answering replies stays on the parent page (no developer chat on the child's phone). Kept out of tv-remote: census `?app=!kidguard` filter, `support.py` refuses KidGuard codes without `--app kidguard`, crashwatch only a desktop notification (never news.txt into tv-remote sessions).
- 2026-11-13 Relay anti-abuse (audit H4/M3): no deploy-time secret (phones auto-bind to the default relay with a random token), so first binds are capped per client network per day (`Gate` DO, 30/day) and a bound-but-never-synced-again id is deleted after 7 days; secrets typed into a command are stripped from the queued copy after the first hand-out (PIN-in-clear on the wire stays accepted, see PIN gate) and the worker drops its unsalted `pinHash` once the phone reports `pinSet` with the rules rev; a 413 state makes the phone send a trimmed state with `relayBig`.
- 2026-11-13 Relay link is shared by all relay parents: removing any device sets state `relayShared`; `relay {renew:true}` (PIN-gated) replaces id + token. Per-parent relay tokens (S4) still open.
- 2026-11-13 Telegram `/code` (owner): the bot replies with the current Authenticator code, seconds left and the next code (read-only, linked chats only), so a parent can read an unlock code without the Authenticator app. Opening admin with it still raises the tamper alert.
- 2026-11-14 Telegram 0.9.16: old button taps are dropped after a > 10 min poll gap (not run on reconnect); answered alerts are edited in every chat from an in-memory (chat, message id) map, lost on restart (old buttons then answer "already answered"); `/quiet` levels are per chat in `chats[].quiet`; bot does not act in groups, only hints once per 10 min.
- 2026-11-14 Scan to add a kid / invite a parent (0.9.17): parent app uses `play-services-code-scanner` (Google code scanner, no CAMERA permission; missing Play services = toast + manual entry). Scanned text is parsed by the same `addRelayLink` as paste, or the kid QR `#pair=`; never opened as a URL. Plain browsers get no scan button (no BarcodeDetector path: a LAN page over http has no camera access). The invite is a QR of the existing relay /go link, no new format.
- 2026-11-14 Kid app pairing card: "Tắt mã ngay" closes a parent-opened pairing code at once (closing only refuses pairing, safe for the kid to tap). Page: turning the relay on re-renders Settings so the Watch section gets its code input (it read cur.relay before the reply).
- 2026-11-14 Pair from anywhere (relay rendezvous `/p/*`, QR invite `kg_invite`): only phones with no parent offer it; the phone decides (`tryPair`), the code is the LAN code, PIN travels to the phone (never in the QR); commit when the page took the link. Details: protocol "Pair over relay".

## Rejected / don't retry
- Sharing GitHub URLs to open updates: the GitHub app hijacks them and the download hung (4445879, 7acef5e)

## Past bugs (cause -> fix -> avoid)
- LAN `rules PUT` kept pinHash without pinSalt -> PIN never matched again. Fix: copy salt with hash. Avoid: treat PIN hash+salt as one unit (1747923)
- sosAck over relay never cleared SOS (random id) -> separate `sos` field (f032b5d)
- Relay re-sent old PIN hash and reverted a PIN set via LAN -> pinAt (f032b5d)
- Child could self-pair (code visible with no parent / no PIN) -> PIN-gated pairing, 24 h recovery (7fc1506)
- Self-update: `at` written before download (24 h wait after failure), only Exception caught, session leak, Policy.apply re-added DISALLOW_INSTALL during update, rejected tag redownloaded -> all fixed 7fc1506
- Parent app WebView render process gone killed the app -> recreate activity (7fc1506)
- Broken pipe on LAN server killed the whole app (Oppo dropbox) -> catch (5f03cbe, Http.kt:61)
