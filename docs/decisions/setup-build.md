- Auto re-grant (2026-11-11, owner: "auto luôn để rút ngắn step"): `setup/AutoGrant.kt` re-runs the setup's own grants (usage, notification listener, deviceidle, location fine+background, POST_NOTIFICATIONS) over self-adb when the checklist finds one missing; every 30 min, 6 h back-off when one won't take. Not done (unverified per OEM): MIUI `AUTO_START` appop, `ACCESS_RESTRICTED_SETTINGS`, `cmd role` HOME; ColorOS "permission monitoring" can't be switched by KidGuard.
- 2026-11-13 Keep app accounts when becoming Device Owner (measured, emulators with a test authenticator app): `pm disable-user --user 0 <pkg>` hides that app's accounts from AccountManager (its authenticator leaves RegisteredServicesCache; `dumpsys account` still lists the DB row, ignore it). API 33: set-device-owner then passes (flaky right after an earlier failed try). API 34: DPMS caches "has incompatible accounts" (`mHasIncompatibleAccounts`, recomputed at boot / LOGIN_ACCOUNTS_CHANGED, which shell may not send): disable, `sync`, reboot, then set-device-owner passes. `pm enable` after: account still there. suspend / per-user uninstall without reboot do not help. System authenticators (Google, Xiaomi, Samsung) still need removal. A first emulator run without the reboot wrongly concluded "impossible".
- 2026-11-13 Keep app accounts, implemented (setup.sh end to end on an API 34 AVD): `pm disable-user` is written to disk ~10 s later, so a reboot right after loses it (use >= 14 s + `sync`); after boot `set-device-owner` still says "accounts" for ~20-30 s, retry every 5 s. Always re-enable (EXIT trap / finally / apps-off file / localStorage / `Store.ownerPending`). Authenticator package must be non-system (`pm list packages -3`), else the parent removes the account. SelfSetup resumes from `Boot`/`Guard.onCreate`, needs the first unlock after boot.
- 2026-11-13 Setup audit fixes: checksum is fail-closed in setup.sh/ps1/install.html (`KG_ALLOW_UNVERIFIED=1` overrides in the scripts); setup.ps1 read `.sha256` via `.Content` (byte[] in Windows PowerShell 5.1, verified on Win10 laptop) and had a parse error (`":$cur:"` read as a scope, use `${cur}`); scripts keep the apps-off record for apps whose `pm enable` failed; install.html/qr.html are Vietnamese + English (table in the page, `kg.lang`, `?lang=`); SelfSetup resume treats a null shell as failure (`ss_conn_lost`). GitHub release downloads are not fetchable from a browser (no CORS), so an install page on the relay needs a worker `/kidguard.apk` proxy.

- (2026-11-18) CI ran NO job from 2026-11-13 (ffd3d50) to 2026-11-18: a step `name:` with an unquoted ": " inside made ci.yml invalid YAML ("workflow file issue", 0 jobs) and every push showed only a red X. ## Rejected / don't retry
- Same-origin APK hosting on the website (/dl/): reverted, back to GitHub release links (9d75f23)
- (2026-11-14) Agent token cost: `docs/flows.md` (~21k tokens whole) split into `docs/flows/<area>.md` (§ numbers kept); `docs/protocol.md` stays ONE file (contract test + setup scripts read it, one grep target) but a whole-file Read of it, `HomeActivity.kt`, `ui/install.html`, `ui/qr.html` is blocked by `.claude/hooks/big-read.py` (project `.claude/settings.json`): grep the heading, Read with offset/limit <= 200.
- (2026-11-14) "Fix" for lost permissions: state `missing` + command `fixPerms` (`guard/FixPerms.kt`): self grants first (DO DPM, WSS accessibility, AutoGrant adb cmds), then open the exact Settings screen on the kid phone + notification; one live band on the parent page, no new section. OEM auto-start is not detectable, so not listed. Spare-the-kid rule: Fix runs only on the parent's tap (AutoGrant still self-heals every 30 min).
- (2026-11-16, owner: "luôn cho kidguard tự bật lại quyền thông báo") What KidGuard can re-enable itself: Android 11+ with its own adb = notification listener + POST_NOTIFICATIONS already, via AutoGrant (checks every 2 min, grants when missing). Android 8-10 (Oppo 8.1): nothing: `enabled_notification_listeners` writes are ignored since Android 8 (86c66de), Device Owner has no API for the listener, and the app notification switch before Android 13 is not a permission (no DPM grant). The page names the cap "Android 11 or newer" instead of "USB debugging" on such phones (capName).
- (2026-11-16, owner: "máy không có quyền mic, không có cách bật từ KG bố mẹ") `mic` joined state `missing` / `fixPerms`: the page banner "N thứ đang tắt" + Fix now covers RECORD_AUDIO (self-adb `pm grant` via AutoGrant, Device Owner grant state, else opens the Permissions screen + a notice on the child). The listen dialog's no-mic answer offers the same Fix instead of a bare OK.
- (2026-11-16) FixPerms for a runtime permission (mic, notify) shows the system "Allow?" dialog from MainActivity (`EXTRA_ASK_PERM`): one tap instead of App info -> Permissions -> Microphone -> Allow. Denied at once (= "don't ask again") falls back to App info.
- (2026-11-17) OEM kill steps (`ui/SetupSteps.kt`): Nam's realme went silent 0:09→4:27+ with Android battery optimisation already off. Auto-start step never showed there (ColorOS 11+/realme keep the safecenter page unexported, `resolveActivity` still matched → now needs `exported && permission == null`, App info fallback on OPPO/realme/OnePlus). OEM switches themselves (autostart DB, oplus battery) have no adb path: stay manual.
- (2026-11-17) Key backup: `scripts/keys.sh backup` packs `android/app/signing.jks` + both `google-services.json` into one AES-256-GCM file (PBKDF2 600k, password typed, never stored; `*.kgkeys` git-ignored), ported from the owner's tv-remote. Keep the file off this computer; `restore` never overwrites a different key. Ed25519-signed SHA256SUMS (tv-remote style) rejected for now: Android's own same-cert update check already blocks a swapped APK.
- (2026-11-18) Owner: "cài nhanh bằng adb wifi mà không có chế độ cơ bản à". Device Owner refused (phone accounts / second user / another owner / provisioned) no longer stops the adb setups: all 4 (SelfSetup, setup.sh/ps1, install.html) fall back to basic mode in the same run (`dpm set-active-admin --user current`, then the usual steps 3-6) and say how to upgrade (remove + rerun). - (2026-11-18, measured on an Android 13 emulator) A refused `dpm set-device-owner` first activates our admin, then removes it again, even an admin that was active before: `set-active-admin` right after fails with "Trying to set an admin which is being removed" for ~1-3 s.
