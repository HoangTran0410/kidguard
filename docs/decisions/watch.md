# KidGuard decisions: watch

Index and the rule for adding lines: `README.md`.

## Decided
- 2026-11-14 Watch connect is a 6-digit code (TV-pairing), not a pasted link: the watch asks the relay for a code (`POST /w/new`, DO `w:<code>`, 10 min), the parent page sends it with the kid's relay auth (`POST /c/<id>/watch`), the side service fetches `{url,id,token,name}` once with its secret. Token = the kid's one relay token (no per-device tokens exist on the relay; only the phone can mint them over LAN); demo phone only after "Xem thử". Paste-the-link stays as a fallback in the Zepp settings page.
- 2026-11-14 Watch map (0.5.0, "Where" page): 2x2 OSM tiles (z13..18, default 16) chosen so the kid is in the centre half, drawn at S/512 scale with CIRCLE dot + accuracy + zone rings. Chain: watch asks side `TILES` for the tiles it lacks -> `network.downloader.downloadFile` (PNG, UA + Referer set) -> `image.convert` (the device cannot show PNG; same PNG->TGA idea as the build) -> `transferFile` outbox -> watch inbox `NEWFILE` -> IMG at the FileObject path. Watch cache `utils/map.js` by z/x/y, keeps 20; the side remembers converted tiles 7 days. OSM tile policy: only what the watch lacks (<=4 per view), cached, identifying User-Agent, "(c) OpenStreetMap" on the map; no prefetch / bulk. Text fallback after 90 s. Not measured on a real watch (transfer speed, UA actually sent).
- 2026-11-14 Watch "Find" mode (0.6.0, owner: "chỉ đường"): page/find.js uses the WATCH GPS (`Geolocation`) + `Compass`, arrow = bearing(me -> kid) - heading drawn with a rotating IMG (assets arrow.png, angle via prop.MORE); kid location re-read every 30 s through side STATE, "Hỏi vị trí mới" = existing locate command; sensors stopped on destroy, `setPageBrightTime` 10 min keeps the screen on. Geolocation has no accuracy field (only valid status A/V), so no "±m" for the watch. Not tested on a real watch (compass axis / calibration).
- Watch map tiles go through the relay (`/c/<id>/tile`, edge-cached) first: the owner's network answers 127.0.0.1 for tile.openstreetmap.org (DNS + SNI block, 2026-11-14), OSM direct is only the fallback. Watch home caches kids + last state in local storage: Zepp rebuilds the page on back, which flashed "no kid" for 1-2 s.
- Watch: zml BasePage owns the file inbox (listens to lowercase "newfile" and takes the file); a page receives files only through its `onReceivedFile(fo)` hook. A page-level `inbox.on("NEWFILE")` never fires: the map stayed empty with every tile delivered. (2026-11-14)
- Watch map tiles (Bip Max): side `downloadFile` WITHOUT `filePath` (with one, convert said "not found"; use the event's `tempFilePath`), download one at a time (temp names come from the URL), convert to a target ending in `.png` (no extension = IMG draws black), IMG `src` = the `data://download/...` path (a `../data/...` path draws nothing). Tiles shown at 256 px and cropped, not `auto_scale`d (scaling untested since the fix). (2026-11-14)
